# Implementation report

**GazeSync: Reproducible Synchronization of Screen Interaction and Multi-Source
Eye Tracking** extends the original GazeSync paper with the independent codebase,
Python/TypeScript contract, multi-source adapters and synthetic verification.

The author list is carried forward from the supplied original manuscript as a
working draft and needs contributor review. This report is not accepted at CHI
and has no implementation arXiv identifier yet. Metadata is explicit in
`metadata.json`; citations to the original and the pending implementation report
are separate in the repository's CITATION files.

[Read the compiled report](GazeSync-implementation.pdf) or edit [main.tex](main.tex).

## Rebuild the data, figures and manuscript

```sh
npm run test:conformance
node tools/paper-data.mjs
.venv/bin/python -m pip install -r paper/requirements.txt
.venv/bin/python tools/paper_figures.py
cd paper
latexmk -pdf -interaction=nonstopmode -halt-on-error main.tex
```

Use Python 3.12+ for the pinned figure-generation environment. The software
library itself supports Python 3.10+. LaTeX needs `acmart` and the packages in
`main.tex` (tested with TeX Live 2025). Figures are reproducible vector PDF/SVG;
the two-column layout uses `sigconf,screen,nonacm` without a conference acceptance,
ACM copyright or fabricated DOI. This is a multi-file manuscript; compile with
its `figures/` directory available.

The checked-in `data/validation.json` records the 78-case result matrix;
`data/timing.json` is the representative synthetic trace. Neither contains human
participant data. Figure 1 explains architecture, Figure 2 exposes the timing
error mechanism, Figure 3 separates camera, eye, panel and viewport origins, and Figure 4 shows
the controlled rate matrix apart from context coverage. All plotted data and
labels can be regenerated by the scripts.

Counts refer to observations: one capture can produce both PoG and ray records
for each eye. Tiny reconstruction residuals are numerical consistency, not gaze
accuracy. Hardware adapters have synthetic contract tests, not physical-device
validation. Context cases vary several factors and must not be pooled as a causal
frequency study. The implementation's release remains disabled until author,
license-scope and citation review is complete.

Manuscript and generated figure publication rights are reserved pending author

are not redistributed in this repository. Edit this independent draft here.


The geometry audit in implementation 0.4.0 adds the origin table, named rigid
transforms, camera-centre inversion, full-display versus viewport plane equations,
marker-to-screen registration and the numerical (860,460) regression. The common
analytic fixtures are in `contracts/geometry-fixtures.json`; they are independent
of the acquisition-rate simulator. See `docs/COORDINATES.md` for practical setup.
Schema 2.1 preserves the plane extent and the metric frame of derived 3D hits.
